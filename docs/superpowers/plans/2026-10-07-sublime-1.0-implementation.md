# Sublime 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a documented, predictable, secure first stable release of Sublime as a lightweight PHP HTML builder.

**Architecture:** Keep the current immutable `HtmlElement` and `TagFactory` model. Make direct rendering of a prebuilt `HtmlElement` or `RawHtml` the ordinary path, retain callback injection as an optional third usage mode, and centralize value normalization so elements, fragments, and callback results share one contract.

**Tech Stack:** PHP >=8.3, Composer, PHPUnit ^12.5, PHPStan ^2.3, PHP CS Fixer ^3.59, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-07-sublime-1.0-design.md`

## Global Constraints

- Runtime requirement: PHP `>=8.3`.
- Runtime dependencies: zero.
- Development tools: PHPUnit `^12.5`, PHPStan `^2.3`, and PHP CS Fixer `^3.59`.
- Child value nesting limit: 128 containers; level 129 throws `InvalidArgumentException`.
- Child `true` renders as `1`; `null` and `false` are omitted.
- Dangerous URL schemes rejected: `javascript:`, `vbscript:`, and `data:text/html`, case-insensitively and after ignoring leading ASCII control/whitespace.
- Three supported usage modes: direct helper functions, an explicitly created `TagFactory`, and optional callback injection.
- CI matrix: PHP 8.3, 8.4, and 8.5; run PHPUnit, PHPStan, and coding standards.

## Review Focus

- A single child passed through `data:` must render identically to a one-item child list; cover in Task 2.
- `true` children and `aria-*`/`data-*` booleans have distinct documented output; cover in Tasks 2 and 3.
- `Stringable` output is escaped once, while unsupported objects/resources throw; cover in Task 2.
- Finite `Traversable` values are consumed once at construction, and excessive or cyclic nesting fails at the 128-level limit; cover in Task 2.
- URL scheme checks must catch mixed-case and leading-control/whitespace variants across all four sensitive attributes; cover in Task 3.
